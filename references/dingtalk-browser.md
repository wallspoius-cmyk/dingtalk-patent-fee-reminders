# 钉钉浏览器操作经验

这些是2026年9月至10月实操观察，不是永久有效的页面 API。先读当前浏览器工具返回的文档，再以实时 DOM、截图和可用连接器为准；不使用隐藏应用状态、猜测接口或脚本注入来改配置。

## 页面与选择器

文档编辑器曾位于 `#wiki-notable-iframe`。绑定实际台账 tab 后，在该 iframe 内定位字段和流程控件。先确认这是用户的真实数据表，避免进入同文档的虚构测试表。

常见操作：

- 数据页的“导入 Excel” → “导入新数据表”，检查预览标题行、申请号、日期和金额，再确认导入；使用浏览器文档提供的 filechooser 流程。
- 在“缴费状态”列标题右键，选择“向右插入列”，可直接把剩余天数放到接收邮箱之前；不要创建到末尾后再猜测拖拽顺序。
- 字段管理中，点击字段名称可能只滚动定位；真正编辑入口通常是该字段旁的更多按钮 → 编辑。
- 若工具栏按钮未显示文字，读取该按钮的可见 UI 属性和图标定位。例如 `_setting16` 曾对应字段管理，必须先观察当前页面证实。
- 公式字段 → 编辑公式 → 填入公式 → 确定编辑器 → 设置显示格式 → 确定字段。新建与转换字段的确认层可能不同。
- 若转换存在数据影响提示，先确认是否已有可替代的源值、能否撤销，以及是否在授权范围；不要将保存公式与确认转换混淆。

流程配置曾出现以下 testid：`node-config-root`、`node-node_start`、`panel-header-close-btn`。只有实时页面确认仍存在时使用。多个关闭按钮可能匹配同一 testid，应限定所属面板；不要按 DOM 顺序盲选。

## 触发与发送

快捷提前选项曾只提供天、周等有限组合；精确30天使用公式日期后选择“日期当天(09:00)”。切换数据表后，旧筛选字段会出现“字段已被删除”，须重新选真实表的缴费状态和值。

下拉中 ARIA option 的文本有时是内部 ID，可见菜单文字才是有效点击目标。选择时依据刚读取的可见名称；不要循环点击失效 option。

QQ 邮件连接配置保留已有账号、收件人、正文类型与UTF-8设置，修改正式主题和正文即可。授权码由用户直接填在服务页面。

钉钉消息可以复用原有接收人和台账按钮。人员选择器可能嵌套在另一个 iframe；搜索正常而点击失败时，可请用户完成选人和确定，保留其选择继续配置。不给用户重复选择已成功保存的收件人。

消息正文曾使用自定义编辑器，与邮件的 contenteditable 文本框行为不同。标题和按钮能编辑、正文不能输入时，先确认正文是否可选；可用标题加台账入口完成最低可用提醒，并明确实际内容。不要不断尝试同一种失效键盘或粘贴动作。

## 保存、状态与故障恢复

- 日期或时间控件填入后可能只改了显示值。日期选择后点击其他单元格，时间输入后 Tab 移走焦点，随后读取已保存值再发布。
- 执行详情“返回编辑”可能把历史版本复制成草稿，即使无改动也显示“有更新未发布”。若需恢复或发布，先核对最终版本；发布完不再为查日志随意回到历史编辑。
- 配置和检查清单面板遮挡流程画布时，点击节点可能无效果。先检查截图并关闭遮挡面板，再选节点；不要把无异常检查结果当作发布成功。
- 观察到每个浏览器操作可能需20多秒。一次调用通常至多放两个慢操作，避免多个操作加截图导致运行超时。执行快时也不依赖这种时延恒定存在。
- 会话中已选浏览器可复用，tab 失效后从同一浏览器重新查找，不反复重选浏览器。运行上下文重置时按工具初始化说明重新绑定。
- 不为读数据盲目刷新已填凭据或未保存配置的页面。若连接故障，先读取工具的排错文档；保留已保存的数据，报告具体未完成步骤。

必要时为无法访问的操作栏临时使用足够宽的视口，完成后恢复默认尺寸。保存最终结果截图并保留台账 tab，说明真实数据是否已发布、未来定时是否尚未发生。
